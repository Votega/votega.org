## GA Overrides System
`assets/data/ga-members-overrides.json` is the mechanism for correcting Open States data and injecting entries (e.g., vacant seats) that Open States doesn't track. When editing:
- Prefer OCD ID keys over name keys for precision.
- Only include fields that need changing — all other fields are preserved from the API.
- Use `_inject` for net-new entries; they must include all required schema fields.
- After changes, re-run `generate_ga_members_soap.py` locally or trigger the `update-ga-members` workflow to regenerate `ga-members.json`. (The Open States producer in `scripts/archive/` predates `_session` scoping, the `_inject` merge and the roster contract; it is not a working fallback.)

- **Key Votes are proposed by a tool and approved by the owner.** `scripts/propose_key_votes.py` (tests: `test_propose_key_votes.py`) ranks recent final-passage roll calls for GA and the federal delegation on neutral signals (outcome, margin, party split, defections, subject) and writes gitignored `out/key-vote-proposals/` (never `assets/data/`, which would deploy unreviewed picks). Only `--approve <id>,...` writes a curated list (`curated-ga-bills.json` / `curated-federal-bills.json`), refusing duplicates; `--dismiss` records declines in `_data/key_vote_decisions.json`. Weekly command and owner steps: RECURRING-TASKS.md §3c. `voteOverride` is documented in TO-DO.md but read by nothing; the generator always picks the final roll call itself.
- **Member ids**: the roster `id` is an opaque handle, not an OCD id (see the `ga-members.json` schema section). Most are `ocd-person/<uuid>`, a member Open States has not catalogued is `legis-<legisGaGovId>`, and injected entries (vacant seats) use synthetic IDs like `ga-senate-7-vacant` — these won't join to vote records. For "does this person have an OCD id", read `ocdPersonId`.
- **`legisGaGovId`**: Numeric ID used by legis.ga.gov to construct `officialWebsiteUrl`. Not used for vote joins — those use the OCD person `id`. Members without it get no official website link. New members from Open States may lack it — add via overrides file.
- **AI bill summaries: reviewed only, and the script is the only writer.** `scripts/ai_enrich_ga_bills.py` (run locally: Ollama `draft`, Claude Code `refine`) writes `assets/data/ga-bill-ai.json`; every entry starts `needsReview: true`. **Entries are keyed `<session>|<identifier>` (`metadata.schemaVersion` 2), the same as `ga-bill-summaries.json`, because bill numbers restart each biennium; every reader (this script, the review tool, `generate_ga_bills_soap.py`) exits with a "run `migrate-keys`" message on an old bare-identifier file rather than guess.** Review happens in `tools/ai-summary-review.html` (open locally in Chrome/Edge, choose the repo root): it reads the AI file, `ga-bills.json` and `curated-ga-bills.json` read-only and appends `approve` (optionally with edited `summary`/`subjects`) / `redo` / `revoke` decisions to `_data/ga_bill_ai_decisions.json` (kept out of the static site so notes stay private), each naming the entry's `generatedAt` as `against`. **Never hand-edit `ga-bill-ai.json`** (a missing comma broke it once): run `apply-reviews`, which is the only writer of review state. It applies the LAST decision per (key, against), so replay is idempotent; a decision on text that has since been re-drafted or refined is reported STALE and never applied; redo/revoke need a note; an edit keeps the model's original once as `aiSummary`/`aiSubjects` and sets `humanEdited`. A re-draft or refine drops all review fields (`REVIEW_FIELDS`), and `refine` takes `redo` entries first, passing the reviewer's note to the model. The site reads only `assets/data/ga-bill-summaries.json` (built by `draft`/`refine`/`apply-reviews`/`publish`): editor `summaryOverride`s, which always win, plus reviewed AI text, keyed `<session>|<identifier>`. `test_ai_enrich_ga_bills.py` fails if that file is out of date with the drafts. AI subject tags reach `ga-bills.json` only through `generate_ga_bills_soap.py`'s reviewed-only, last-resort AI layer (`subjectsSource: "ai"`), never via `ga-bills-subjects.json`. Key Votes uses override > reviewed AI > caption (`summarySource`). Every AI summary on the site is labeled as AI and links to `about-the-data#ai-bill-summaries`.
- **A legislator URL never 404s; the ledger is append-only; never delete from `ga-bienniums/`.** Any URL `votegaUrl` has ever pointed at must still resolve (the page, or a `redirect_to` stub to it). Do not hand-edit `ga-legislator-ledger.json`, drop a member from `search-entities.json`, or remove a frozen file; a name/district change adds a ledger URL, it never replaces one. The freeze (`freeze_ga_biennium.py --all`) is a required rollover step BEFORE the `--new-biennium` run (RECURRING-TASKS.md §3). Departed members (Resigned/Removed/Deceased) have pages too, so do not treat a null/absent `votegaUrl` as "left the legislature".
- **Georgia Civic Data / Georgia Commons collaboration: read `docs/georgia-civic-data-collaboration.md` first.** It records what is built (5-digit county FIPS and the district-to-county files in `ga-district-information`, the Newton findings, the suspended-seat handling), what Georgia Commons offers, `votegaUrl` on roster records (live, with a drift test), and the open steps: ask Georgia Commons to link sponsors to `votegaUrl`, link-outs to their bill pages with AI-summary labelling, no copying of their text until a license is confirmed, an optional slim `counties` field on members, the MCP server, and school-district joins through tracts.
- **Seat history: read `docs/seat-history-design.md` before modelling an office, a district or a term.** Design settled 2026-11-20 (all decisions D1–D9); only Phase 0 is built (the staged executive turnover above). Facts that were expensive to establish and are easy to get wrong:
  - **A districted seat is its set of census blocks, never its number.** Comparing the reapportionment office's 2021 and 2023 block-equivalency files (all 232,717 blocks) showed the 2023 maps left 41 of 56 Senate, 119 of 180 House and 5 of 14 congressional districts (GA-1, 2, 3, 8, 12) untouched, while 30 redrawn legislative districts and 2021 GA-6 (now mostly GA-7) moved under a different number, and 2021 HD 149 is block-for-block 2023 HD 133. Treating a re-adopted plan as all-new would falsely close 165 holds; joining by number joins the wrong constituencies. Decide identity from the block files, never from the act's name or the district number.
  - **seatId = office + the map that first drew it, written once and never renamed** (`ga-house-15@2021` is today's HD 15; `ga-house-61@2023` was redrawn; `us-senate-ga-class-2`; `local:newton:district-3@m1`). Never a holder's name or a term year; findability comes from URL slugs and JSON-LD, which may change behind redirects. Every local seat is on map `m1` unless its jurisdiction declares it `jurisdiction_wide`, because publishing a districted seat without a map is the irreversible mistake.
  - **`endedBy` records only why THIS hold ended** (`term-limited`, `did-not-run`, `lost`, `resigned`, `removed`, `deceased`, `redistricted`, `term-ended`); a win or loss in another race is derived from the same vgId's next hold or its candidacies, never stored. Vacancies are computed from holds (facts go in `vacancyNotes`); a suspension is a status inside the hold; an appointment is an ordinary hold with `appointed: true`.
  - History is scoped from January 2023; it publishes (later) as one dataset in `Votega/ga-district-information`. The 2021 and 2023 block-equivalency workbooks are local inputs in `data-inputs/redistricting/` (gitignored; `data-inputs/README.md` lists each with source and MD5); Census block population (`gageo2020.pl`) is needed only for lineage-link population shares.
- **A federal URL never 404s either: former members keep frozen pages (D12 option B).** `scripts/freeze_federal_congress.py <slug> --final` (RECURRING-TASKS.md §3b step 5, by 2027-01-02, BEFORE the roster flips to the 120th) copies the sitting Georgia delegation's record into `assets/data/federal-congresses/<slug>/` (live file names; `freeze.json` carries each member's page `urls`, which is the permanence record: no separate ledger). `build_entity_pages.build_federal_legislators` builds a "Former member" page, indexed and in the sitemap, for every frozen member the live roster no longer lists, at the promised URL; their ids sit under `entity_urls['us-congress-former']`, NOT `['us-congress']` (the race and candidate pages read that one as "sitting"). The page include reads every per-Congress file through `dataUrl()` in frozen mode (`test_federal_former_pages.py` fails on a bare live path) and never joins the live `presidential-laws.json` (bill numbers restart each Congress). Departure labels (D6 wording) come only from the approved `assets/data/federal-departure-labels.json`; drafts are `docs/federal-departure-labels-draft.md`.
- **January 2027 biennium rollover: read `docs/ga-biennium-rollover-decisions.md` before touching the roster, bills or member-page generation.** It lists what the rollover drops (non-returning members, their page URLs, bill-number reuse), the open decisions (former-member pages, bills session dropdown with a frozen prior biennium, departure wording), and the 2027-01-11 deadline. Nothing in it is built yet.

## Governor's veto messages and signing statements (yearly, after the signing deadline)

legis.ga.gov carries a veto's NUMBER (`ActVetoNumber` "V1") but not the message. The Office of the Governor posts one
PDF a year at https://gov.georgia.gov/executive-action/legislation/vetoed-legislation/<year> ("<year> Veto Messages and
Signing Statements"). After the signing deadline (mid-May; a special session has its own), once the bills workflow has
recorded the Governor's actions:

    python scripts/import_governor_statements.py <year> <session tag> <the PDF's download URL>

It writes `assets/data/ga-governor-statements.json` word for word and refuses unless every VETO n is a bill
ga-bills.json has as vetoed that year and every vetoed bill has a message. The next bills run attaches them
(`governorStatements`, `governorAction.vetoNumber`); the bills page shows them in the tracker and the MCP's `get_bill`
returns them. The same page links the budget's line-item vetoes and "disregard" statements, which are not imported.
