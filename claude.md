# Agent Instructions for votega.org Project

## Scope
These instructions apply only to the votega.org project (a static GitHub Pages Jekyll site). They do not affect other projects or general coding tasks.

## Project Overview
VoteGA.org is a static GitHub Pages Jekyll site for Georgia voter information. It displays federal and state legislators, election info, and civic topics.

**Tech Stack:** Jekyll (Beautiful Jekyll theme) · Congress.gov API · GitHub Actions · Python · JavaScript · Public Sans + Font Awesome (brand: "Georgia Peach & Clay")

**Data Flow:**
```
Congress.gov API → GitHub Actions → Python script → assets/data/*.json → JS lookup → HTML pages
```

## Commands
```bash
bundle exec jekyll serve --port 4000 --livereload   # local site (also the "jekyll" entry in .claude/launch.json)
python scripts/build_entity_pages.py                # generate entity pages before a full jekyll build
python scripts/test_<name>.py                       # each scripts/test_*.py runs standalone; CI runs them all
python scripts/validate_workflow_triggers.py        # run before pushing any workflow change
```

## Project Structure (short map)
Full annotated tree: `docs/project-structure.md`. Run `git ls-files` for the current set.
- **Pages:** top-level `*.html` / `*.md` (federal, GA legislature, elections/races, executive/judicial, topics); entity pages are generated by `scripts/build_entity_pages.py`.
- **Templates:** `_layouts/`, `_includes/` (incl. `_includes/entity/*` page logic), `_posts/`, `_data/` (`data_freshness.yml`, `freshness/`).
- **Data:** `assets/data/*.json` is generated by GitHub Actions from `scripts/` (Python, `scripts/lib/` shared); never hand-edit generated files. Client JS in `assets/scripts/`; tokens in `assets/css/tokens.css`.
- **Workflows:** `.github/workflows/` (`update-*.yml` per dataset, `publish-*` to sibling repos `Votega/*`, `deploy-pages.yml`); failures are watched by `notify-workflow-failure.yml`.
- **Local tools:** `tools/*.html` are standalone editors (open in Chromium); `docs/` holds designs, runbooks and the reference files below.

## Core Principles
- **API Key Security First**: Never expose API keys in client-side code. Use build-time generation (GitHub Actions) to fetch data and serve static JSON. If live API calls are needed, implement a proxy.
- **Static Site Best Practices**: Prefer prebuilt data over dynamic fetches to avoid CORS issues and key exposure.
- **Congress.gov API Handling**: Fields are `partyName` (direct), `terms.item[-1].chamber` (the most recent term; terms run oldest → newest) for chamber. Always filter client-side for state/chamber — the API doesn't support direct chamber queries. Note API limitations in UI (e.g., no contact info).
- **Error Handling**: Clear, actionable error messages for users ("Data file missing—run the workflow"). Log errors to console for debugging. Python scripts should `sys.exit(1)` on fatal errors so workflows catch failures.
- **Environment Awareness**: Detect GitHub Pages paths and adjust redirects accordingly.
- **GitHub Actions**: Use secrets for sensitive data. Schedule workflows for daily updates. Validate data integrity (count thresholds + required fields) before committing — never commit based on JSON validity alone.

## Coding Patterns
- **First-party JS/CSS is cache-busted; keep the `?v=` suffix on every new script tag.** Every `{{ '/assets/scripts/*.js' | relative_url }}` reference carries `?v={{ site.time | date: '%s' }}`, so a new build's HTML always requests a URL the browser/edge cache doesn't hold — HTML and its JS can never be mismatched. This exists because `votega-core.js` is edge- and browser-cached for 4h (`max-age=14400`): shipping HTML that called a new global (`VotegaPortraits`) added by an as-yet-uncached `votega-core.js` `ReferenceError`'d and blank-screened every entity page, and a Cloudflare purge can't reach a returning visitor's already-cached JS. When you add a first-party `<script>`/stylesheet tag, append the same `?v={{ site.time | date: '%s' }}` (see `_includes/head.html`); every stylesheet rendered by the `common-css` / `site-css` / `page.css` loops in `_includes/head.html` (incl. `beautifuljekyll.css`, which the brand work edits, and `cards.css`) is versioned the same way; only vendored JS (`/assets/js/*`) and the unchanged `staticman.css` are left unversioned. Belt-and-suspenders: still guard bare references to any newly-added `votega-core.js` global with `window.X ? …`.
- **Colors come from role tokens, never raw hex.** `assets/css/tokens.css` is two layers: palette values (`--clay-500`, `--pine-600`, …) and role tokens (`--color-text`, `--color-link`, `--color-accent`, `--color-surface-*`, `--color-border*`, `--color-success/warning/danger` + `-tint`/`-line`, `--color-party-*`, `--chart-*`, `--color-watch-*`). Components, page `<style>` blocks and JS-built markup use ONLY role tokens (`var(--color-…)`); palette tokens appear only inside `tokens.css`. A new color means a new role token there, not a literal in a page. The theme's own config colors (`page-col`, `link-col`, … in `_config.yml`) are set to role tokens, so a future dark theme overrides roles in one block. Brand rules that are easy to break: **each party has ONE color used for that party and nothing else** (`--color-party-d/-r/-i/-vacant`, with `-tint` for badge backgrounds and `-text` for small text on tint; Independent is magenta, Vacant is gray); the brand palette has no blue or red, so UI never uses them; **status colors (success / warning / danger) always come with an icon and a label**, and danger is for real errors only (empty / unavailable / known-gap messages are amber or gray); categorical chart series use `--chart-*`, which avoid the party hues and were chosen for color-blind separation (re-check with a color-vision simulation before adding a series).
- **`var()` does not work everywhere.** A `<canvas>` `fillStyle` cannot take `var(--token)`: resolve it first (see `tokenColor()` in `assets/scripts/ga.js` and `ga-executive.html`). SVG built in JS should set color through `style="fill:var(--…)"`, not a presentation attribute. Never append a hex alpha suffix to a color string (`color + '22'`); use `color-mix(in srgb, var(--color-…) 15%, transparent)`.
- **Icons are Font Awesome, not emoji** (`<i class="fa-solid fa-…" aria-hidden="true"></i>`, loaded sitewide). The one exception is the legacy `emoji` field in `_data/topics.yml` / `generate_topic_mentions.py`, kept only because it is part of the published topic dataset; the site renders the `icon` field instead. Monospace for IDs and order numbers is `var(--font-mono)`; body and headings are Public Sans (400/600/700, 400 italic; there is no 800).
- **Public Sans is wider than the old body face, so check containers at 375 and 1280.** A flex row of figures inside a fixed-width card (e.g. the congress-trades member cards) can spill out of its own border. Let such rows `flex-wrap`, and verify new cards and chips at both widths; whole-page overflow checks do not catch content leaking out of its own box.
- **JavaScript**: `async/await` for fetches. `fetch()` over XMLHttpRequest. Constants at top (e.g., `DATA_URL`).
- **Resolve every data/asset URL through `getBasePath()`, never bare-relative.** A `fetch('assets/data/…')` is resolved against the *current page*, so it only works at the site root (legacy `/race.html`, `/candidate.html`). On the clean entity URLs (`/races/<slug>/`, `/ga-legislators/<slug>/`, `/us-congress/<slug>/`, `/candidates/<slug>/`) a bare-relative path resolves *under the entity directory* and 404s silently — the fetch returns not-ok, the loader yields `null`, and the UI shows a false "data unavailable". This is easy to miss because it passes on the root page you're probably testing. Applies especially to **shared JS modules** (`campaign-finance.js` and friends) that run on both root and entity pages — the module must build its own base-path prefix, not assume the page did it. Mirror the `getBasePath()` helper the entity includes already use (the site is served at the domain root, so it returns `/`; see `assets/scripts/votega-core.js`). Verify any finance/data change on a clean `/races/<slug>/` URL, not just `/race.html?id=…`.
- **HTML**: Semantic elements. Fallback links (e.g., back to search page). Inline scripts for simplicity.
- **Python**: `urllib` for requests (no third-party HTTP libs except where already present). Paginate with `while True` loops. Output clean JSON with a `metadata` object containing at minimum `generatedAt` (ISO timestamp) and `count`. Use `None` for missing optional fields — never empty strings.
- **Python retries**: Retry on HTTP 429 and 5xx only. Return `None` immediately on 4xx — these are non-retryable client errors.
- **Workflows**: `ubuntu-latest` runners. Validate output data before committing (count thresholds, required-field spot checks, metadata.count == len(members)).

## Always-on rules (full detail in the linked docs)
- **Never commit secrets** — only generated JSON files go back to the repo via workflows.

- **UX**: Show loading states, handle empty/null data gracefully, explain API limitations in UI.

- **Identity & URLs are permanent.** Roster `id` is an opaque handle; `legisGaGovId` is the key. vgIds, `ga-legislator-ledger.json` and `ga-bienniums/` are append-only. A published legislator or federal URL never 404s. -> `docs/conventions-ga-legislature.md`, `docs/data-schemas.md`.
- **Never put a status word ("unofficial", "certified") in a post filename/slug/permalink.** -> `docs/conventions-elections.md`.
- **Renaming a workflow `name:` means editing `notify-workflow-failure.yml` in the same commit.** -> `docs/conventions-publishing.md`.
- **Writers are guarded:** use `lib/atomic_io.py` for data writes; every sibling publish goes through `publish_or_dry_run`; every in-place `races.json` mutator calls a `lib/races_guard.py` check. -> `docs/conventions-publishing.md`, `docs/conventions-elections.md`.
- **A new dataset needs a stale-stamp window** in `_data/data_freshness.yml` and a recorder call in its workflow. -> `docs/conventions-general.md`.
- **Pages that render sibling-published data link the published `Votega/*` repo, not `assets/data/*`.** -> `docs/conventions-publishing.md`.

## Hard-won traps (one line each; the linked doc has the story)
**Data & votes** (`docs/data-schemas.md`)
- Congress.gov member endpoints must be paged to the end; a failed page means `null`/carry-forward, never a short list published as fact.
- A missing House roll call is HTTP 200 with an error body: decide on content, stop after consecutive misses. Never read pass/fail from one keyword ("Agreed to" passed).
- GA pass/fail is never yea > nay: a bill needs a majority of all seats (91 House / 29 Senate, vacancies don't lower it), and two-thirds (120/38) for constitutional amendments and local tax-exemption acts, in EVERY biennium, not just the current one. One rule, `lib/ga_vote_rules.py`; check against official status with `check_ga_vote_status.py` (313 lost votes once showed as Pass).
- GA vote chamber comes from the record's `chamber`, never from `motionText`. Read/write `ga-member-votes.json` only through `lib/votes_schema.py`.
- senate.gov 403s non-browsers: Senate votes fall back to Voteview (`lib/voteview.py`), replaced when senate.gov is reachable again.
- Executive orders: `pubDate` is not the signing date; join Register and whitehouse.gov on normalized title plus EO-number cross-check, never body-text numbers. Always date-filter Federal Register queries (10,000 is the API cap, not a count).
- `ga-zip-districts.json` means districts *touching* a ZIP: never drop a small share. State shares are estimated from tracts; do not reintroduce the county route.
**Identity & rosters** (`docs/data-schemas.md`, `docs/conventions-ga-legislature.md`)
- Departures live only in `ga-members-overrides.json` (biennium-scoped by `_session`); an `_inject` for a member the source now returns is merged, not skipped.
- A rollover is never the daily run's job: freeze (`freeze_ga_biennium.py --all`) BEFORE `--new-biennium`; federal freeze `--final` by 2 Jan (Congress number flips 00:00 UTC on 3 Jan).
- Never key identity on a races.json candidate id (positional) or on an identifier slot (`ocdPersonId`); use `legis:<id>`, bioguide, `peachfile:`/`fec:`. Merge two vgIds with `sameAs` (forward), never rewrite; never take a vgId from `alias()`'s return value.
- A districted seat is its census blocks, never its number; decide carry-over from the block files.
**Elections** (`docs/conventions-elections.md`)
- Election night: use the SoS JSON feed URL (the XLSX name carries a fresh GUID), keep `fill_missing` ON for unofficial counts. Wait for certification before updating results from unofficial exports.
- Results pages: stage them indexable with every contest in the served HTML (an empty-looking page is a soft 404); only `status: certified` pages publish to ga-races-elections, and a missing count is blank, never 0. Full checklist: "Results pages and publishing".
- Never drop a retired candidate from `search-entities.json` (page builders read it back and would delete the page). Share cards are generated at deploy, never committed.
**Local government** (`docs/conventions-local-government.md`)
- Never overwrite good data with worse: judge a re-read by lost findings, not lost characters. Meeting-topic keywords are measured against the corpus, never guessed; the scorer and probe never carry a private keyword list.
- An `aka` is another NAME for the same organization, never a relationship (`c/o`, affiliates, individuals).
- Read minutes with `pdftotext -raw`, never `-layout`.
**Publishing** (`docs/conventions-publishing.md`)
- Bot commits (GITHUB_TOKEN) fire no `on: push`: dispatch the deploy explicitly. Add a new sibling repo to `REPO_SOURCES` and `REPO_PUBLISHERS` before publishing to it.
- Publish a new artifact BEFORE adding its `_data/open_data.yml` entry, or the link validator goes red until the publisher runs.
- Published schemas: `$id` built from the artifact's own path, carry `schemaVersion`; never add `required` to an existing schema.
- Portrait cache: government hosts only, skip-if-cached (never re-download). A stamp means "content last changed", not "the job ran".

## Enforcement
- Check for API key exposure before suggesting any code changes.
- If proposing live API calls, suggest static/build-time alternatives first.
- For new features, verify against Congress.gov API docs and test with sample data.
- When modifying the member shaping in `generate_ga_members_soap.py` / `lib/ga_roster.py`, ensure all schema fields are present in the output — missing fields cause silent JS failures downstream.
- Do not use empty strings for optional fields — use `None`/`null`.
